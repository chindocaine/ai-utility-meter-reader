1. Reference image

Upload a clean, well-lit photo of the meter. This defines the coordinate space for every digit ROI below.

Correct perspective (optional)

For a camera mounted off-axis to the meter display: drag out the display's 4 corners in order (top-left, top-right, bottom-right, bottom-left) - drop a corner with a click, then drag it before releasing to fine-tune, and drag any already-placed corner again any time to adjust it. The whole image is then warped so the traced area becomes rectangular (nothing is cropped away). Nothing is saved until you click "Apply perspective correction", which bakes it into the reference image and clears any existing ROI boxes. Alignment against live photos already uses a full homography, so it keeps working automatically after this.

Straighten (optional)

Preview a rotation to correct camera skew before drawing ROIs - it's much easier to line up horizontal digit boxes on a de-skewed image. Nothing is saved until you click "Apply rotation", which bakes it into the reference image and clears any existing ROI boxes (their old coordinates would no longer line up).

Image quality (optional)

Boost brightness, contrast and sharpness for a dim or slightly hazy camera. Baked into the reference image (like straighten/perspective above) so it's computed once instead of on every capture - but kept as its own step, from a separate untouched checkpoint, so you can retune and re-save it any time without needing to redo perspective/rotation first. The same values are also applied to every captured image before alignment and digit cropping. The preview below is rendered by the backend itself, so it matches exactly what gets baked in.

7. Outlier protection

Applied to every accepted reading (test runs show the effect but don't write history) - a rejected reading keeps the previous value/timestamp in place and surfaces an error instead of writing bad data to history, Home Assistant or MQTT.



Override last accepted reading

If a long gap without a successful reading meant the meter genuinely advanced further than "reject a lower reading" or "max allowed increase" would otherwise accept, set the true current value here - it's recorded as the new baseline (as if it were the last accepted reading) so the next real reading is checked against it instead.
